## 0. 공통 규칙

- 모든 호출 `temperature=0`
- 호출 일시·모델명·응답 원본·토큰을 **전량 저장** (`runs.jsonl`)
- 표와 그림의 모든 수치는 저장 자료에서만 산출
- 중단 복구: 완료된 문항 id를 보고 이어서 실행

### 모델 등급

| 등급 | 용도 |
|---|---|
| 저가 `MODEL_CHEAP` | 주 실험 대상 · 재작성기 · LLM 축 변형기 |
| 고가 `MODEL_EXPENSIVE` | 주 실험 대상 · 번역 · 심판 |

**2등급으로 축소.** 중가 등급은 버렸다 — 등급을 늘리는 것보다 축을 살리는 쪽이
정보를 더 준다. 등급은 환경변수로 주입하고, 모델명을 코드에 하드코딩하지 않는다.

### WildChat을 쓰지 않는다 · 축소

원안은 개방형 문항을 WildChat 실제 대화 로그로 채우는 것이었다. HuggingFace
이용 약관 동의와 선별·정제에 반나절이 걸려 마감 안에 들어오지 않는다.

→ 개방형은 **연구자가 작성한 대체 문항**을 쓰고, **이를 한계로 명기한다.**
"실사용 프롬프트"라는 기여는 앵커의 `ko_human`(사람이 직접 친 문장)이 받친다.

여유가 생겨 WildChat을 넣는다면 선별 기준은 이렇다.

- 첫 턴(user)만 사용. 개인정보·유해 내용 포함 시 제외
- 유형별로 명확히 분류되는 것만 (요약/상담/계획/글쓰기)
- 한국어 우선, 부족하면 영어 문장을 번역하지 말고 그대로 사용하되 별도 표기
- 선별 기준과 제외 사유를 `data/wildchat_selection.md` 에 기록

## 2. Part A — 엉성함의 대가

### 조건 — 기준선 · 축 변형 · 자연복합

"엉성함"은 한 덩어리가 아니다. 축으로 쪼개야 **어느 엉성함이 비싼지** 알 수 있고,
그래야 서비스가 "이것 하나만 고치세요"라고 말할 수 있다.

```
기준선    잘 쓴 한국어 질문
축 변형   기준선을 한 가지 방식으로만 망가뜨린 것
자연복합  사람이 실제로 쓴 것 — 여러 축이 뒤섞인 현실
```

| | 기준선 | 축 | 자연복합 | 보너스 |
|---|---|---|---|---|
| 앵커 | `ko_expert` 모델 번역 | 3축 · 축소 | `ko_human` 사람이 작성 | `en_expert` 영어 원문 |
| 개방형 | `refined` 재작성기 | 3축 · 축소 | `original` 사용자풍 원문 | — |

### 8개의 축

| 가족 | 축 | 이름 | 생성 |
|---|---|---|---|
| 표면 잡음 | S1 | 오타·자모분리 | 규칙 |
| | S2 | 어순 도치 | 규칙 |
| | S3 | 구어체·줄임말 | LLM |
| 정보 결핍 | D1 | 맥락 생략 | LLM |
| | D2 | 지시 부재 | 규칙 |
| | D3 | 지시어 모호 (개방형 전용) | LLM |
| 정보 과잉 | E1 | 사족·잡담 | LLM |
| | E2 | 무관 붙여넣기 | 규칙 |

규칙 기반 4축은 시드를 고정해 재현 가능하게 한다. 구현은 `perturb.py`.

### 실행하는 축 — 3축 · 축소

8축 전수는 시간이 없다. **가족별 1개씩** 골라 세 가족을 모두 대표하게 한다.

| 축 | 가족 | 생성 | 고른 이유 |
|---|---|---|---|
| **S1** 오타·자모분리 | 표면 | 규칙 | 규칙 기반 재현 가능 · "대가 없음"이 나와도 서비스 메시지가 된다 |
| **D1** 맥락 생략 | 결핍 | LLM | 가장 치명적일 것으로 예상 · 제품 메시지("출발지만 넣으세요")에 직결 |
| **E2** 무관 붙여넣기 | 과잉 | 규칙 | 토큰을 직접 낭비하는 축 · 이 연구 주제에 가장 잘 맞는다 |

3축 중 2축이 규칙 기반이라 재현성 강점이 유지된다.
여유가 생기면 되살릴 순서는 **D2 지시 부재 → E1 사족·잡담 → S3 구어체** 다.

**신호가 없는 축도 결과다.** 판단 기준은 정답률 3%p 이상 하락 또는 토큰 1.15배 이상.

> **구현 상태 — 반영 완료** (D-15). `perturb.ACTIVE_AXES` 가 실행할 축을 정하고,
> 8축 정의(`ALL_ANCHOR_AXES` · `ALL_OPEN_AXES`)는 되살릴 수 있게 남겨 두었다.
> 축을 늘리려면 `ACTIVE_AXES` 한 줄만 고치면 된다.
>
> 무과금 리허설에서 **결핍 > 과잉 > 표면** 순으로 대가가 찍히는지 확인할 수 있다.
> 그 순서가 안 나오면 분석 코드가 깨진 것이다.

### 세 가지 비교

```
축별 대가    기준선 vs 각 축         → 어느 엉성함이 제일 비싼가
언어 대가    en_expert vs ko_expert  → 한국어라서 치르는 값
합성 타당성  축들 vs 자연복합         → 합성이 사람을 재현하는가
```

셋째에서 자연복합이 **어떤 단일 축보다 나쁘면**, "합성 축의 단순 합으로는 사람의
엉성함을 재현하지 못한다"가 그 자체로 결과가 된다.

번역은 고가 모델로 수행하고, **숫자·조건 누락이 없는지 표본을 눈으로 확인**한다.
LLM 기반 축도 의도대로 변형됐는지 표본 확인이 필요하다.

`ko_human` 은 **두 사람이 서로 안 보고 각자 한 벌씩** 쓴다. 한 명분을 주 실험에 쓰고,
남은 한 벌로 **방향이 일치하는지** 확인한다.

### 다회차

첫 답이 오답이면 고정 문구로 **1회 되묻는다** (최대 2턴).
그때까지 쓴 토큰을 모두 청구한다. 개방형은 오답 판정 기준이 없으므로 1턴.

### 측정

| 지표 | 앵커 | 개방형 |
|---|:---:|:---:|
| 정답률 | ✓ | — |
| 쌍대 승률 | ✓ (심판 검증용) | ✓ |
| 체크리스트 충족률 | — | ✓ (요약·계획) |
| 입력·출력 토큰 | ✓ | ✓ |
| 턴 수 | ✓ | — |

### 검정

같은 문항의 짝지어진 정오이므로 **McNemar**. 작성자 수와 무관하게 성립한다.

**군집 부트스트랩은 쓰지 않는다 · 축소.** 작성자가 2명이면 군집 간 분산을 표본 2개로
추정하는 셈이라 자유도가 1이고, 신뢰구간이 나와도 의미가 없다.

대신 추론을 주장하지 않고 **관찰을 보고한다.**

```
작성자 A의 문장에서 엉성함의 대가 −N%p
작성자 B의 문장에서 엉성함의 대가 −M%p
→ "두 작성자 모두에서 같은 방향" (강건성 확인, 신뢰구간 주장 없음)
```

*"작성자 한 명의 문체 때문에 나온 결과 아닙니까"* 라는 반박을 정면으로 막아준다.
문항 20개로는 애초에 유의성을 주장하지 않으므로 톤도 일관된다.

## 3. 심판 규격

### 쌍대 비교

- 시스템 프롬프트에 "길다고 좋은 것이 아님"을 명시 (길이 편향 억제)
- **순서를 바꿔 두 번** 묻고, 판정이 뒤집히면 무승부 처리
- 뒤집힘 비율을 **위치 편향 지표**로 보고

### 체크리스트

문항마다 4개 항목. 심판이 항목별 0/1. JSON 배열만 출력하도록 강제.

### 심판 검증 ★

앵커 문항 중 **한쪽만 정답인 쌍**에서, 심판이 정답 쪽을 골랐는지 센다.

| 심판 정확도 | 조치 |
|---|---|
| ≥ 85% | 그대로 진행 |
| 70–85% | 심판 프롬프트 수정 또는 더 큰 모델 |
| < 70% | **개방형 수치를 논문에 싣지 않는다.** 심판부터 고친다 |

위치 편향이 30%를 넘으면 심판이 내용이 아니라 순서를 보고 있다는 뜻이다.

## 4. Part B — 재작성의 손익분기

### 조건 — 2종 × 2등급 = 4조합 · 축소

```
· 무재작성  — 개방형의 original (사용자풍 원문)
· 재작성    — 개방형의 refined  (재작성기가 다듬은 것)
```

단순/구조화 2종으로 나누는 것은 버렸다. Part A 실행에서 이미 `original` 과 `refined`
가 함께 생성되므로, **추가 호출 없이 같은 자료에서 Part B를 산출한다.**

재작성기는 **저가 모델 하나로 고정**한다. 재작성 비용을 정확히 계측하기 위해서다.

### 비용 정의

```
총비용 = 재작성 입력·출력 토큰 + 본 질의 입력·출력 토큰
```

단가 환산 시 등급별 입력/출력 단가를 별도 적용한다.

> **재작성 호출의 토큰을 반드시 `runs.jsonl` 에 남길 것.**
> 앞항을 버리면 Part B를 사후에 계산할 수 없고, 다시 계산하려면 실험을 다시 돌려야 한다.
> 번역(`ko_expert` 생성) 토큰도 같이 남긴다 — 이쪽은 사용자 비용이 아니라 실험 장치
> 비용이므로 총비용에 넣지 않되, 실험 원가를 보고할 때 쓴다.

### 최적화

```
minimize   총 토큰 비용
subject to 품질 ≥ (무재작성 + 고가 모델) − ε
           ε ∈ {0, 1, 3, 5} %p
decision   재작성 여부 × 모델 등급   (4조합)
```

품질 지표는 앵커는 정답률, 개방형은 체크리스트 충족률을 쓴다.

ε를 키우며 비용이 떨어지는 곡선을 그리면 **"정확도 1%p를 몇 토큰에 사는가"** 가 나온다.

### 손익분기 추정

문항을 입력 길이와 난이도로 나누고, **재작성 순이득이 0을 지나는 지점**을 회귀로 추정한다.

```
순이득 = (무재작성 총비용) − (재작성 총비용)
```

### 보고 방식 주의

조합을 쌍별로 전수 비교하면 검정 횟수가 빠르게 늘고, 보정 없이는 전체 1종 오류가
급격히 커진다(원안 9조합 = 36비교 → 84%). 4조합으로 줄여도 **원칙은 그대로다.**

- 주 보고: **파레토 경계 포함 여부**
- 검정: 사전 지정한 핵심 대비 **하나만** 적용 — `무재작성+고가` vs `재작성+저가`
- 문항 20개이므로 유의성보다 **방향과 크기**를 보고한다

## 5. Part C — 한도 배분

**추가 API 호출 없음.** Part A·B의 (조건 → 비용, 정답률) 실측표를 시뮬레이터 입력으로 쓴다.

### 설정

```
하루 질문 K개가 순차 도착. 각 질문은 난이도 d, 중요도 w를 가진다.
총 한도 B. 도착 시점에 (재작성 여부, 모델 등급, 건너뛰기) 중 하나를 고른다.
미래 질문은 모른다.
목표: 한도 안에서 가중 정답 수 최대화.
```

### 정책

| 정책 | 내용 |
|---|---|
| 사후 최적 | 하루치를 전부 알고 푼 **다중선택 배낭 정확해(DP)** |
| 현재 관행 | 모든 질문을 고가 모델로 |
| 고정 임계 | 난이도 임계 하나로 등급 분기 |
| **제안 · 쌍대가격** | 아래 |

### 쌍대가격 규칙

```
λ = λ₀ / (남은 예산 / 남은 질문 수)

각 등급 g에 대해   순가치 = w · p(g, d) − λ · c(g)
순가치가 최대인 g를 선택. 전부 음수면 건너뛴다.
```

조정 파라미터는 **λ₀ 하나뿐**이다. 사전 시뮬레이션에서 λ₀ = 0.15 부근이 좋았다.

### 난이도 추정 오차

실제 서비스에서는 난이도를 분류기로 **추정**해야 한다.
따라서 추정 오차 σ 를 **정식 실험 요인**으로 둔다 (σ ∈ {0, 0.1, 0.2, 0.3, 0.45}).

사전 시뮬레이션에서 고정 임계는 σ가 커지며 78% → 63% 로 무너지고,
쌍대가격은 99% → 96% 로 버텼다. 이 **견고성**이 Part C의 주 주장이다.

### 자동 검사 (필수)

**사후 최적 대비 달성률이 100%를 넘으면 코드 오류로 간주하고 중단한다.**
근사 오라클을 쓰다 상한이 깨진 전례가 있다 (`DECISIONS.md` D-03).

### 평가

- 사후 최적 대비 달성률
- **한도 소진 시각** — "하루 40개 중 몇 번째 질문에서 막혔는가".
  사용자가 체감하는 지표라 포스터에서 설명이 필요 없다.

`analyze.py` 출력이나 집계 파일을 따로 전달한다.

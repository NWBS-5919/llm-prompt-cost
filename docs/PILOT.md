# 파일럿 v4 — 실행 매뉴얼

엉성함을 8축으로 쪼개 재는 파일럿의 운용 문서.
프로젝트가 무엇인지는 [`../README.md`](../README.md), 전체 기획은 [`PROJECT.md`](PROJECT.md).

문항 20개로 **이틀 만에 다섯 가지**를 확인한다.

1. **어떤 종류의 엉성함이 제일 비싼가** ← 이번 판의 핵심
2. 한국어라서 치르는 값은 얼마인가
3. 합성으로 만든 변형이 사람이 쓴 것을 재현하는가
4. 그 손해가 수학·코딩 밖에서도 나타나는가
5. 정답 없는 질문을 채점할 AI 심판을 믿어도 되는가

---

## 왜 축으로 쪼개나

v3까지는 "엉성함"을 **한 덩어리**로 봤다. 그런데 실제 질문 하나를 뜯어보면 여러 문제가
섞여 있고, **무게가 전혀 다르다.**

> "잘 찾아주 ㅓ 집 가는 경로를"

- **오타** "주 ㅓ" — 요즘 모델은 그냥 알아먹는다. 손해가 거의 없다
- **어순 도치** — 한국어는 어순이 자유롭다. 영향이 미지수다
- **맥락 생략** 출발지가 없다 — **치명적.** 되묻거나 경우를 다 나열하느라 답이 몇 배로 길어진다

한 덩어리로 보면 *"질문이 엉성하네요"* 밖에 못 말한다.
쪼개면 **"오타는 괜찮습니다. 출발지만 넣으세요"** 가 된다. 완전히 다른 제품이다.

## 8개의 축

세 가족으로 묶었다. 성격이 근본적으로 다르다.

### 가족 1 · 표면 잡음 — 정보는 다 있고 글자만 망가짐

| 축 | 이름 | 생성 | 예시 |
|---|---|---|---|
| **S1** | 오타·자모분리 | 규칙 | `친구4먕이 피자 4판을 총 64달러에 시켰다 ... 두 판의거겨은 같다` |
| **S2** | 어순 도치 | 규칙 | `두 판의 가격은 같다. 그중 두 판이 30달러였다면, 나머지 두 판은 각각 얼마인가? 친구 4명이 피자 4판을 총 64달러에 시켰다.` |
| **S3** | 구어체·줄임말 | LLM | `ㅇㅇ 친구4명이서 피자4판 64불 시켰는데 두판이 30불이면 나머지 두판 각각 얼마임?` |

### 가족 2 · 정보 결핍 — 글자는 멀쩡한데 정보가 없음

| 축 | 이름 | 생성 | 예시 |
|---|---|---|---|
| **D1** | 맥락 생략 | LLM | `친구 4명이 피자 4판 시켰는데 64였다. 두 판이 30이면 나머지는?` (단위 소실) |
| **D2** | 지시 부재 | 규칙 | 형식·분량·단계 요구를 전부 제거 |
| **D3** | 지시어 모호 | LLM | `아까 그거 다시 정리해줘` — **개방형 전용** |

### 가족 3 · 정보 과잉 — 쓸데없는 게 붙음

| 축 | 이름 | 생성 | 예시 |
|---|---|---|---|
| **E1** | 사족·잡담 | LLM | `아 진짜 오늘 너무 정신없는데 잠깐 하나만 ... (질문) ... 고마워 진짜` |
| **E2** | 무관 붙여넣기 | 규칙 | 복사하다 딸려온 웹페이지 메뉴·이전 대화 조각이 앞뒤에 붙음 |

**8축 중 4축이 규칙 기반**이다. 시드를 고정하면 누구나 똑같이 재현된다.
`python3 perturb.py` 로 규칙 축의 실제 출력을 바로 볼 수 있다.

## 조건 구조 — 앵커와 개방형이 같다

```
기준선    잘 쓴 한국어 질문
축 변형   기준선을 한 가지 방식으로만 망가뜨린 것
자연복합  사람이 실제로 쓴 것 — 여러 축이 뒤섞인 현실
```

| | 기준선 | 축 | 자연복합 | 보너스 |
|---|---|---|---|---|
| **앵커** (수학·코딩) | `ko_expert` 모델 번역 | 7축 | `ko_human` 팀원 작성 | `en_expert` 영어 원문 |
| **개방형** (요약·조언·계획·글쓰기) | `refined` 재작성기 | 8축 | `original` 사용자풍 원문 | — |

각 10조건, 문항 20개 → **약 830회 호출, 1만 원 안쪽, 20분.**

### 여기서 나오는 세 가지 비교

```
축별 대가    기준선 vs 각 축        → 어느 엉성함이 제일 비싼가
언어 대가    en_expert vs ko_expert → 한국어라서 치르는 값
합성 타당성  축들의 합 vs 자연복합   → 합성이 사람을 재현하는가
```

셋째가 특히 중요하다. 사람이 쓴 것이 **어떤 단일 축보다도 나쁘면**,
*"합성 축의 단순 합으로는 사람의 엉성함을 재현하지 못한다"* 가 그 자체로 결과가 된다.

## 실행

```bash
# 0. 환경 변수
export LLM_BASE_URL="https://api.openai.com/v1"
export LLM_API_KEY="sk-..."
export MODEL_CHEAP="..."        # 주 실험 대상 · 재작성기 · 축 변형기
export MODEL_EXPENSIVE="..."    # 기준선 · 번역 · 심판

# 1. 문항 만들기
python3 prepare.py

# 2. 규칙 축이 어떻게 생겼는지 눈으로 확인 (무과금)
python3 perturb.py

# 3. 사람이 할 일 — 앵커 10문항만 (아래 참조)

# 4. 배관 점검 (무과금)
python3 run_pilot.py --fake && python3 analyze.py

# 5. 실제 실행
rm -f runs.jsonl && python3 run_pilot.py && python3 analyze.py
```

### 3번 — 사람이 할 일

`novice_TODO.csv`의 `novice_ko` 열을 채운다. **두 사람이 서로 안 보고 각자 한 벌씩** 쓰고,
파일럿엔 한 명분만 쓴다. 남은 한 벌은 방향이 일치하는지 확인하는 데 쓴다.

- 원문을 **번역하지 말고**, 그 문제를 내가 AI에 물어본다면 어떻게 칠지 그대로
- "단계별로 풀어라" 같은 지시문을 일부러 넣지 않기
- **맞춤법 고치지 않기** — 이게 자연복합 조건의 핵심이다

개방형 10문항은 손댈 필요 없다.

## 결과 읽는 법

### ① 축별 대가 ★

각 축이 기준선 대비 정답률을 얼마나 깎고 토큰을 얼마나 늘렸는지. 가족별 평균도 함께 찍힌다.

**본실험으로 가져갈 축 고르기**

- 정답률 **3%p 이상** 하락 또는 토큰 **1.15배 이상**인 축만 남긴다
- 가족별로 최소 한 개씩은 남겨 세 가족을 모두 대표하게 한다
- **신호가 없는 축도 결과다** — *"오타는 대가가 없다"* 는 그대로 서비스 메시지가 된다

### ② 언어의 대가

5%p 이상이면 독립된 발견으로 보고한다.
토큰 배율(한국어/영어)은 정답률과 무관하게 그 자체로 의미가 있다.

### ④ 심판 검증

| 심판 정확도 | 조치 |
|---|---|
| ≥ 85% | 그대로 진행 |
| 70–85% | 심판 프롬프트 수정 또는 더 큰 모델 |
| < 70% | **⑤의 수치를 논문에 싣지 않는다.** 심판부터 고친다 |

위치 편향이 30%를 넘으면 심판이 내용이 아니라 순서를 보고 있다는 뜻이다.

> `--fake` 모드에서는 심판이 무작위로 답하므로 정확도가 낮고 위치 편향이 높게 찍힌다.
> 정상이다. 분석이 그걸 잡아내는지만 보면 된다.

## 주의

**파일럿은 유의성 검정이 아니다.** 20문항으로는 큰 차이도 p값이 0.05를 넘는다.
방향과 크기만 본다.

**코딩 채점은 모델이 만든 코드를 실제로 실행한다.** 개인 계정이나 격리된 환경에서
돌릴 것. 무한 루프는 8초로 끊는다.

**`runs.jsonl`을 지우지 말 것.** 모든 조건의 프롬프트·답변·토큰이 들어 있다.

**번역과 축 변형을 한 번은 눈으로 확인할 것.**

```bash
python3 -c "
import json
r = json.loads(open('runs.jsonl').readline())
for k, v in r['prompts'].items():
    print(f'--- {k}\n{v[:180]}\n')
"
```

번역이 숫자를 빠뜨리면 기준선이 무너지고, LLM 축이 의도와 다르게 변형하면
축 해석이 틀어진다.

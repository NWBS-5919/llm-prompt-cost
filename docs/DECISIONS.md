# 결정 로그

무엇을 왜 그렇게 정했는지. **코드나 설계를 바꿀 때 여기에 한 줄 남긴다.**
심사위원이 "왜 이 방법이냐"고 물으면 대부분의 답이 여기 있다.

## D-01 · 주제를 "실제 사용자 프롬프트의 비용"으로 잡은 이유
`2026-09` · 확정

LLM 비용 연구(FrugalGPT, RouteLLM, DSPy, LLMLingua)는 전부 **연구자가 다듬은
벤치마크 프롬프트**로 실험했다. 실제 사용자는 그렇게 묻지 않는다.

실사용 프롬프트를 쓴 연구(ACL 2026 분포 이동)는 **정답이 없어 LLM 심판에 의존**했고,
본인들이 이를 한계로 명시했다.

→ **정답이 있는 문제를 사람이 다시 묻게 하면** 두 세계가 합쳐진다.
표현만 바뀌고 나머지는 동일한 **통제 실험**이 되고, 자동 채점도 된다.

## D-02 · 표본 설계를 "적은 사람 × 많은 문항"에서 뒤집은 이유
`2026-09` · 사전 시뮬레이션으로 발견

초안은 30명 × 10문항 = 300개였다. 그런데 **한 사람이 쓴 프롬프트는 서로 닮아 있어**
(문체·생략 습관) 독립 표본이 아니다. 참가자 내 상관 ICC=0.2 를 넣으면:

| 설계 | 유효표본 | 검정력(격차 10%p) |
|---|---:|---:|
| 30명 × 10문항 | 107 | 0.46 |
| 60명 × 5문항 | 167 | 0.70 |
| 80명 × 5문항 | 222 | 0.83 |

**1인당 문항 수가 설계효과를 지배한다.** 사람을 늘리고 1인당 문항을 줄이는 쪽이 맞다.

> **후속 · D-06 에서 이 결정은 무효화됐다** (참가자 모집 자체를 포기).
> **후속 · D-14** — 작성자가 2명이 되어 군집 추론 자체를 포기했다.
> 다만 "군집이 유효표본을 깎는다"는 사실은 여전히 유효하므로, 두 사람의 결과를
> 합치지 않고 **각각 보고해 방향이 일치하는지만** 본다.

## D-03 · 사후 최적을 DP 정확해로만 계산하는 이유
`2026-09` · 버그로 발견

Part C 첫 시뮬레이션에서 제안 정책이 "사후 최적"을 **130% 달성**하는 결과가 나왔다.
가치/비용 비율로 정렬한 **탐욕 근사**를 오라클로 썼기 때문이다. 상한이 상한이 아니었다.

비용이 정수 단위이므로 **다중선택 배낭 DP**로 정확해를 구할 수 있다. 바꾸자 모든 수치가
100% 아래로 정렬됐다.

→ **달성률이 100%를 넘으면 코드 오류로 간주하고 중단하는 자동 검사를 넣는다.**

## D-04 · Part C 정책을 적응 임계에서 쌍대가격으로 바꾼 이유
`2026-09` · 사전 시뮬레이션으로 발견

초안 정책은 *"남은 한도 비율에 따라 난이도 임계를 조절"* 이었다.
돌려보니 **예산이 빠듯할수록 단순한 고정 임계보다 나빴다.**

| 예산 | 현재 관행 | 고정 임계 | 적응 임계(초안) | **쌍대가격** |
|---|---:|---:|---:|---:|
| 넉넉 B=400 | 71.8% | 90.1% | 93.4% | **95.9%** |
| 보통 B=220 | 40.4% | 94.2% | 92.3% | **95.7%** |
| 빠듯 B=140 | 28.5% | 77.9% | **64.4%** | **95.9%** |
| 매우빠듯 B=90 | 18.0% | 55.9% | **42.6%** | **97.1%** |

원인 — B=90에서 선택 분포를 보면:

```
적응 임계 : 고가 3회(42점) + 중가 10 + 저가 8 → 90점 소진, 19문항 미처리
쌍대가격  : 고가 0회 + 중가 14 + 저가 26     → 82점 소진, 40문항 전부 처리
```

초안은 *"어려운 질문엔 고가 모델"* 이라는 규칙을 한도가 빠듯한데도 고집했다.
쌍대가격은 **"지금 내 한도 사정에서 고가 모델은 수지가 안 맞는다"** 고 판단해
아예 쓰지 않았다.

→ 규칙을 고정하지 말고 **토큰 1단위의 그림자 가격**을 남은 예산으로 계속 다시 매긴다.
조정 파라미터는 λ₀ 하나. 건너뛰기도 선택지에 포함한다.

## D-05 · 난이도 추정 오차를 실험 요인으로 승격한 이유
`2026-09` · 보강

D-04 결과는 난이도를 정확히 안다는 비현실적 가정 위에 있었다. 오차 σ를 주고 다시 돌리니:

| σ | 현재 관행 | 고정 임계 | 쌍대가격 |
|---|---:|---:|---:|
| 0.00 | 28.4% | 78.3% | **99.3%** |
| 0.20 | 28.5% | 71.4% | **98.2%** |
| 0.45 | 28.9% | **62.6%** | **96.2%** |

고정 임계는 무너지고 쌍대가격은 버틴다. **견고성**이라는 새 주장이 생겼으므로
σ를 정식 실험 요인으로 둔다.

## D-06 · 참가자 모집을 포기하고 두 갈래 설계로 바꾼 이유
`2026-09-22` · 마감 단축(10/5)으로 불가피

참가자 80명 모집·동의·수집에만 2주가 걸린다. 남은 기간 전부다.

→ 엉성한 프롬프트를 얻는 경로를 **두 갈래**로 나눈다.

```
앵커    벤치마크 원문 → 팀원이 평소 말투로 다시 씀 (모집 아님, 반나절)
개방형  WildChat 실제 문장을 그대로 씀 → 재작성기가 다듬음
```

> **후속 · D-14** — 팀이 2인으로 확인되어 `ko_human` 은 2벌이 된다.
> 개방형의 WildChat 교체는 마감 때문에 보류하고 연구자 작성 문항을 쓴다.

개방형 쪽이 **참가자 없이 진짜 사용자 프롬프트를 확보**해 준다.
D-01의 기여("실사용 프롬프트 + 정답 채점")가 갈래를 나눠 둘 다 유지된다.

## D-07 · 과제를 수학·코딩에서 6종으로 넓힌 이유
`2026-09-22` · 설계 오류 수정

초안은 **자동 채점이 되니까** 수학·코딩만 썼다. 이는 **도구에 맞춰 연구 질문을 깎은 것**이다.
만들려는 서비스는 아무 질문이나 다루는데 실험이 두 종류뿐이면 외적 타당성이 없고,
심사위원이 제일 먼저 찌를 곳이다.

핵심은 **정답률이 유일한 측정치가 아니라는 것**이다.

```
① 답이 틀린다     → 정답 필요        → 앵커
② 답이 별로다     → 쌍대·체크리스트   → 개방형
③ 토큰을 더 먹는다 → 정답 불필요       → 전부
```

→ 앵커(수학·코딩) + 개방형(요약·상담·계획·글쓰기) 두 갈래.
개방형은 심판으로 채점하고, **그 심판을 앵커로 검증한다**(D-08).

---

## D-08 · 심판을 앵커 문항으로 검증하는 이유 ★
`2026-09-22` · 핵심 설계

개방형 채점은 LLM 심판에 의존할 수밖에 없고, *"그 심판을 왜 믿냐"* 는 반박이 반드시 온다.

우리는 **정답을 아는 앵커 문항이 있다.** 거기에도 똑같이 심판을 붙여, 한쪽만 정답인 쌍에서
심판이 정답 쪽을 골랐는지 세면 **심판의 정확도를 수치로 말할 수 있다.**

> 우리 심판은 정답이 확인된 문항에서 N% 일치했다.
> 따라서 개방형 판정도 그 정도 신뢰도로 읽으면 된다.

**ACL 2026 분포 이동 논문은 정답이 없어 이 검증을 할 수 없었다.**
같은 도구(LLM 심판)를 쓰면서도 우리가 한 걸음 앞에 서는 지점이다.

위치 편향도 함께 통제한다 — 순서를 바꿔 두 번 묻고, 뒤집히면 무승부.

## D-09 · Part B를 파레토 경계로 보고하는 이유
`2026-09` · 통계

재작성 3종 × 모델 3등급 = 9조합을 쌍별로 전수 비교하면 36번이 된다.
보정 없이 α=0.05 로 비교하면 **적어도 하나가 우연히 유의할 확률이 84%** 다.

검정은 사전 지정한 핵심 대비 2~3개에만 적용한다.

## D-11 · 앵커에 한국어 정제판을 끼워 넣은 이유 (언어 교락)
`2026-09-22` · 설계 오류 수정

v2 앵커는 **잘 쓴 것 = GSM8K 영어 원문**, **엉성한 것 = 팀원이 쓴 한국어**였다.
두 조건 사이에서 **언어와 엉성함이 동시에 바뀐다.** 차이가 나도 원인을 가를 수 없고,
심사위원이 바로 찌를 지점이다.

→ 앵커를 3조건으로 나눈다.

```
en_expert  영어 원문 + 지시문
ko_expert  같은 문제의 한국어 정제판 (고가 모델이 번역)
ko_novice  팀원이 쓴 평소 말투

엉성함의 대가 = ko_expert vs ko_novice   (언어 고정)
언어의   대가 = en_expert vs ko_expert   (엉성함 고정)
```

번역은 모델이 하므로 사람 손은 늘지 않는다. 앵커 호출만 1.5배가 되는데
파일럿 기준 250회 수준이라 비용 영향은 무시할 만하다.

**부수 효과 — 교락이 발견으로 바뀐다.** 언어 효과를 따로 재면
*"한국어 사용자는 이중으로 손해본다 — 언어 때문에 한 번, 엉성하게 물어서 또 한 번"*
이라는 독립된 주장이 생긴다. 한국 학회 포스터에 특히 잘 맞는다.

개방형 문항은 이미 전부 한국어이므로 교락이 없고 2조건을 유지한다.

**남은 위험** — 번역판이 원문의 숫자·조건을 빠뜨리면 `ko_expert` 가 기준 역할을
못 한다. 표본을 눈으로 확인하는 절차를 실험 규격에 넣었다.

## D-12 · 엉성함을 한 덩어리에서 8개 축으로 쪼갠 이유
`2026-09-22` · 설계 확장

v3까지 "엉성함"은 단일 조건이었다. 그런데 실제 질문 하나를 뜯어보면 여러 문제가
섞여 있고 **무게가 전혀 다르다.**

> "잘 찾아주 ㅓ 집 가는 경로를"
> · 오타 — 모델이 알아먹는다. 대가가 거의 없을 것
> · 어순 도치 — 한국어는 어순이 자유롭다. 미지수
> · 출발지 누락 — 치명적. 답이 몇 배로 길어진다

한 덩어리로 두면 *"질문이 엉성하네요"* 밖에 말할 수 없다. 쪼개면
**"오타는 괜찮습니다. 출발지만 넣으세요"** 가 된다. 제품이 달라진다.

→ 세 가족 8축으로 분해한다.

```
표면 잡음   S1 오타·자모분리 / S2 어순 도치 / S3 구어체·줄임말
정보 결핍   D1 맥락 생략 / D2 지시 부재 / D3 지시어 모호(개방형 전용)
정보 과잉   E1 사족·잡담 / E2 무관 붙여넣기
```

**가족 3(정보 과잉)을 처음에 빼먹고 있었다.** 토큰을 직접 낭비하는 축이라
이 연구에 가장 잘 맞는데도 그랬다. 사족·잡담과 복붙 노이즈는 실제로 아주 흔하다.

8축 중 4축을 규칙 기반으로 구현해 시드 고정 재현이 가능하게 했다(`perturb.py`).
논문에서 재현성 강점이 된다.

**비용은 문제가 아니다.** 파일럿에서 8축을 전부 돌려도 약 830회 호출, 1만 원
안쪽이다. 그래서 **파일럿에서는 넓게 깔고, 본실험에서는 신호 있는 4~5축만** 가져간다.
탐색 후 확정.

**신호가 없는 축도 결과다.** "오타는 대가가 없다"는 그대로 서비스 메시지가 된다.

## D-13 · 규모를 키우기로 한 이유 (문항 수·유형 수)
`2026-09-22` · 범위 조정

참가자를 쓰지 않으므로 **문항 수 = API 비용**뿐이다. 계산해보니 현재 90문항 계획은
1.4만 원, 10배로 늘려도 13.7만 원이다. 90문항은 명백히 적다.

또 과제 유형 6종을 **연구자가 상상해서 정한 것**도 잘못이다. 실제 분포에서 뽑아야 한다.
WildChat 대화를 유형 분류해 **많이 묻는 순서대로 10~12개**를 쓴다.
그 분포 자체가 포스터 그림 하나가 된다 — 우리가 정한 게 아니라 데이터가 정했다는 게 세다.

**규모 계획**

| | 1차 (필수) | 2차 (여유 시) |
|---|---|---|
| 앵커 | 60 | 150 |
| 개방형 | 120 (12유형 × 10) | 300 |
| 축 | 파일럿에서 선별한 4~5 | 동일 |
| 호출 | 약 12,500 | 약 31,000 |
| 비용 | 약 10만 원 | 약 26만 원 |

마감이 10/5이므로 1차를 먼저 완주하고, 시간이 남으면 2차로 넓힌다.

> **이 결정은 D-14 에서 무효화됐다.** 9/22–28 진행이 없어 규모를 키울 시간이 사라졌다.
> 다만 "문항 수 = API 비용뿐이므로 사람보다 계산을 늘려라"는 판단 자체는 유효하며,
> 마감 후 확장할 때 다시 이 표를 기준으로 쓴다.

## D-14 · 규모를 키우는 대신 줄이고, 파일럿과 본실험을 합친 이유
`2026-09-29` · 일정 실패에 대한 대응

**9/22–28 진행이 없었다.** 파일럿을 돌리지 못했고 `novice_ko` 10칸도 비어 있다.
원래 일정(9/26–29 본실험)에서 7일 밀렸고 마감까지 6일 남았다.

### 파일럿을 관문으로 쓰는 계획을 접는다

파일럿의 목적은 *"이 방향으로 갈지 말지 결정"* 이다. 그런데 6일 남은 시점에서
**"멈춰라"는 판정이 나와도 선회할 시간이 없다.** 관문을 통과시키려 830회를 쓰고
본실험 12,500회를 또 쓰는 것도 불가능하다.

→ **한 번 실행해 그 수치를 논문에 쓴다.** 판정 절차는 남기되, 그 결과는
진행 여부가 아니라 **어느 주장에 무게를 실을지**(11절 표)를 고르는 데 쓴다.

### 무엇을 줄였는가

| 항목 | 원안 | 축소 | 근거 |
|---|---|---|---|
| 축 | 8축 전수 | **3축** S1·D1·E2 | 가족별 1개씩. 2축이 규칙 기반이라 재현성 유지 |
| 문항 | 180 (D-13) | **20** | 기존 `items.json` 그대로 사용 |
| 모델 등급 | 3 | **2** | 등급보다 축이 정보를 더 준다 |
| 개방형 출처 | WildChat | **연구자 작성** | 약관 동의·선별에 반나절. 한계로 명기 |
| Part B 조건 | 재작성 3종 × 3등급 = 9 | **2종 × 2등급 = 4** | Part A 자료에서 추가 호출 없이 산출 |
| 검정 | 군집 부트스트랩 | **방향 일치 확인** | 작성자 2명으로는 군집 간 분산 추정 불가 |

호출 수는 약 830회 → **약 500회(추정)** 로 줄어든다. 실행 전 `--fake` 로 확인한다.

### 팀이 2인이다

문서 전체가 3인 기준으로 쓰여 있었다. `ko_human` 은 2벌이 되고, 역할 분담도
3역할(데이터·실험·최적화)에서 2트랙으로 합친다.

작성자 2명이면 **군집 부트스트랩이 성립하지 않는다** — 군집 간 분산을 표본 2개로
추정하는 셈이라 자유도가 1이고, 신뢰구간이 나와도 의미가 없다. McNemar는 같은 문항의
짝지어진 정오를 보므로 작성자 수와 무관하게 유효하다.

→ 추론을 주장하지 않고 **두 사람의 결과를 각각 보고해 방향이 일치하는지만** 본다.
*"작성자 한 명의 문체 때문 아닙니까"* 라는 반박을 정면으로 막아준다.

### 되돌릴 순서

여유가 생기면 이 순서로 복원한다. 앞쪽이 정보 이득이 크다.

```
1. 축 복원        D2 지시 부재 → E1 사족·잡담 → S3 구어체
2. 문항 확대      앵커 60 + 개방형 120 (D-13 표)
3. 개방형 교체    WildChat 실제 한국어 문장
4. 모델 등급      중가 추가
```

### 남은 위험

줄인 축에서 정작 큰 신호가 있었을 수 있다. 특히 **D2 지시 부재**는 앵커에서 효과가
클 것으로 예상되는데 제외했다 — 채점 형식 지시까지 제거해 `grade.py` 의 숫자 추출이
폴백으로 떨어지고, 그러면 축의 대가와 채점 실패가 섞인다. 이 문제를 제대로 다루려면
채점 지시문을 축 변형에서 분리해야 하는데(D-15), 3축 안에서는 우선순위가 낮았다.

## D-15 · 실행 전에 코드 6군데를 고친 이유
`2026-09-29` · 실행 준비

돈을 쓰기 전에 고쳐야 하는 것과, 결과를 잘못 읽게 만드는 것을 나눠 처리했다.

### 돈을 쓰기 전에 고쳐야 했던 것

**① 재작성·번역 호출의 토큰을 버리고 있었다.**

```python
ref, _, _ = chat("rewriter", ...)    # 토큰을 받아서 버림
```

Part B의 총비용 정의가 *"재작성 토큰 + 본 질의 토큰"* 인데 앞항이 `runs.jsonl` 에
남지 않았다. 즉 **RQ2(그림 2)를 사후에 계산할 수 없었다.** 실행 후에 발견하면
실험을 다시 돌려야 한다. `rec["setup"]` 에 기록하도록 바꿨다.

**② 축 변형이 채점 지시문까지 망가뜨리고 있었다.**

축을 `본문 + 지시문` 전체에 적용해서, S1(오타)이 *"최종 답만 '정답: ' 형식으로 써라"* 를
같이 훼손했다. 그러면 모델이 그 형식을 안 쓰고, `grade.py` 가 **"본문의 마지막 숫자"**
폴백으로 떨어진다. GSM8K 풀이의 마지막 숫자는 정답이 아닌 경우가 흔하다.

→ 축의 측정된 대가에 **"채점기가 파싱에 실패했다"** 가 섞인다. 게다가 지시문 제거는
이미 **D2(지시 부재) 전용 축**이므로, 다른 축에 D2 성분이 들어가 축 분리라는
D-12의 전제가 흐려진다.

수정 — 축은 **질문 본문에만** 적용하고 지시문은 그 뒤에 붙인다. D2는 지시문을
아예 붙이지 않는 것으로 정의해 정규식 제거보다 정확해졌다.

**③ 축을 3개로 줄였다** (D-14). `perturb.ACTIVE_AXES` 한 줄로 정하고,
8축 정의는 `ALL_*` 로 남겨 되살릴 수 있게 했다. 호출 834회 → 473회.

### 결과를 잘못 읽게 만들던 것

**④ 무과금 리허설이 축을 구분하지 못했다.** 가짜 모델의 판정이
`"step by step" in txt` 였는데 한국어 기준선과 모든 축이 여기에 걸리지 않아
**전부 같은 확률(0.50)** 을 받았다. 리허설 결과가 순수 노이즈라서 *"분석이 맞게
계산되는지"* 를 확인할 수 없었다 — 리허설의 존재 이유가 사라진 상태였다.

수정 — 조건 이름을 `tag="cond:<조건>"` 로 넘겨 축마다 확률을 다르게 준다.
이제 **결핍 > 과잉 > 표면** 순서가 리허설에서 재현되고, 그 순서가 안 나오면
분석 코드가 깨진 것으로 판단할 수 있다.

**⑤ Δ 부호가 표와 요약에서 반대였다.** 표는 `acc − base`(양수=개선), 가족별 평균은
`base − acc`(양수=하락)를 쓰면서 둘 다 "하락"이라고 적었다. `-6.7%p 하락` 같은
이중부정이 찍혔다. **"대가"(양수=손해)** 하나로 통일했다.

### 판정 기준을 사람이 쓴 문장에서 축으로 옮겼다

**⑥** 1차 판정이 `ko_human`(저자 본인이 쓴 엉성한 문장) 기준이었다.

```python
gap = (base_a - nat_a) * 100      # ← 가장 편향된 측정치로 판정
```

작성자가 **논문의 저자 2명**이고 실험 목적이 *"엉성하면 손해"* 임을 안다. 그 상태로
"평소 말투로 써라"는 지시를 받으면 **엉성함을 연기하게 된다**(요구특성 편향).
심사위원이 *"직접 엉성하게 쓰신 문장으로 엉성함의 대가를 재신 거죠?"* 라고 물으면
답이 없었다.

반면 **축 변형은 결정론적 규칙·고정 프롬프트로 만들므로 작성자 편향이 원리적으로
불가능하다.** 논리를 이렇게 바꿨다.

```
전: 사람이 엉성하게 쓰면 N%p 손해다         → 저자가 쓴 문장이라 방어 불가
후: 맥락을 빼면 N%p 손해다 (결정론적 변형)   → 편향 불가능
    그리고 사람이 쓴 문장도 같은 방향이다    → 보조 증거
```

`ko_human` 은 ③합성 vs 자연 비교와 보조 증거로 남기고, 출력에 편향 경고를 붙였다.

### 부수 — `novice_ko` 를 한국어본에서 쓰게 했다

작성자가 영어 원문을 읽기 어려워 CSV에 `ko_reference` 열(같은 문제의 한국어본)을
넣었다. 이게 설계상 **더 맞다** — 영어를 보고 한국어를 쓰면 작성자의 번역 선택이
섞여 들어가 D-11이 분리하려던 언어 효과가 다시 엉킨다. 한국어본에서 출발하면
언어가 고정되고 엉성함만 변한다.

`ko_reference` 는 **사람이 읽는 참고자료일 뿐 실험 조건이 아니다.**
`ko_expert` 조건은 여전히 실행 시 `MODEL_JUDGE` 가 생성한다.
